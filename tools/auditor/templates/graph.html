    How to read this graph
    • lane — the theories/ import layer the entry is formalised in, derived from its source files and ordered left → right exactly as tools/check_layers.py enforces it: Foundations, Measurable, Linear ∥ Stable, Exponential, CBV, PPL. Two lanes are drawn as a pair of stacked bands (homs ∥ stable, kernels ∥ exp) because those directories are parallel: neither may import the other {% if graph_meta %}{{ graph_meta.lanes | length }} lanes{% endif %}
    • ⚑ leaf — nothing in any tab depends on it, and it does rest on something: a headline result rather than machinery. Leaves are not confined to the right-hand lanes — a lane says where a result is proved, not how far up the stack it sits. The Leaves button lights them all at once {% if graph_meta %}{{ graph_meta.n_leaf_results }} across all tabs{% endif %}
    • root — the complementary, quieter mark: it depends on no other documented entry, so it is where a reading of that lane can start. Entries with no entry-level dependency in either direction carry this mark too rather than the leaf flag {% if graph_meta %}{{ graph_meta.n_roots }} across all tabs, {{ graph_meta.n_isolated }} of them isolated{% endif %}
    • depends — a real Coq proof dependency read from the .glob files: this entry's lemma uses an identifier the target documents. The arrowhead sits on the dependent end, so every arrow runs left → right, from a lemma to the result resting on it {% if graph_meta %}{{ graph_meta.n_depends }} across all tabs{% endif %}
    • against the lane order — a real dependency whose source sits left of its target, i.e. the one shape the lane reading does not predict. Two distinct causes, counted apart because they are not the same defect: {% if graph_meta and graph_meta.n_lane_backward_multilayer %} {{ graph_meta.n_lane_backward_multilayer }} point at an entry documenting files from several layers, which the lane rule places by its deepest one — the layout is honest, the entry is simply wider than a lane; {% endif %} {% if graph_meta and graph_meta.n_lane_backward_contested %} {{ graph_meta.n_lane_backward_contested }} point at an entry whose files all live in one layer, so placement cannot be the cause: these come from identifier ownership — the entry claims an identifier that is defined or re-used in another layer, and every use of it is then attributed here.
